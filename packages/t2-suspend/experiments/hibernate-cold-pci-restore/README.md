# Guard-assisted atomic restore runtime

This offline candidate has distinct identity `cold-pci-guard-fullrestore-v1`, bundle `/usr/lib/omarchy-t2-cold-pci-restore/`, intent `/run/omarchy-t2-cold-pci-restore.intent`, environment inputs `OMARCHY_T2_COLD_PCI_RESTORE_BUNDLE` and test root `OMARCHY_T2_COLD_PCI_RESTORE_ROOT`. It derives pending-path checks from the historical combined pre-architecture diagnostic without modifying that profile. It carries the same explicitly pinned corrected PCI guard and carries no abort module.

The bundle contains `functions`, `guard.ko`, `guard.sha256`, `guard.srcversion`, `restore.variable`, `header-reader`, `header-reader.sha256`, `resume.device`, `resume.offset`, `resume.devnum`, `stock-resume` and `stock-resume.sha256`. The strict synchronous hook sequence is `encrypt`, `omarchy-t2-cold-pci-restore`, `omarchy-t2-restore-marker`, `resume`, `omarchy-t2-cold-pci-restore-stop`. The stock resume file must be the exact pinned existing production hook. No systemd asynchronous resume helper may intercept it.

An exact PENDING swap header and unconsumed V2 marker authorize explicit guard insertion. The runtime requires exact module file/source identities, pristine one-use parameters, BCE bound to that guard, ANS bound to nvme, exact four Apple function IDs, and unbound SEP/audio siblings. It rejects abort modules, competing BCE modules and historical same-vector return witnesses. Immediately before resume it rechecks marker, Entered/Armed hook witnesses, guard identity, armed matching prefix and zero inactive nonfailed gates. The unchanged guard performs its corrected ANS controller completion and disabled-ownership checks inside freeze_noirq before clearing and saving sibling MASTER bits; userspace cannot substitute a pre-resume sample for those PM-time gates.

The pending stock resume call is intended to execute actual atomic restoration. Successful transfer never returns to this restore initramfs. Every return, including an ordinary zero status, stops visibly in recovery and exits init if the shell exec returns. The pending path is latched before the call, preventing consumed headers or deleted intent from opening the ordinary path. No success witness is written here: restored source execution and the separate source runner must prove restoration. The final stop hook is a second continuation guard. NORMAL/no-marker boot requires all experimental modules absent and permits candidate late payload without loading any guard or abort.

The positive historical controlled return demonstrates a guard gate and recovery at architecture entry only. Posted DMA drain, firmware isolation, image copying and restored source recovery remain unproven. This directory is offline runtime design, not builder/registry integration, boot qualification, staging or authorization for hardware transitions. Preserve production kernel and command-line sections byte-for-byte and every consumed hardware guard.
