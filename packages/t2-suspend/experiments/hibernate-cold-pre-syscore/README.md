# Cold pre-syscore controlled-abort prototype

This is a new standalone module and test design, with no builder, auditor, hook or runner integration and no hardware qualification. Do not modify, restage or repeat the consumed cold pre-CPU image/vector. This experiment must receive a distinct image, experiment identity, marker/witness identity and one-use guard through later reviewed integration. The production `.linux` and `.cmdline` sections must remain byte-identical.

The target is `syscore_suspend()` entry in the cold restore kernel. In the pinned production source, `resume_target_kernel()` first requires successful `dpm_suspend_end(PMSG_QUIESCE)` and platform preparation, then calls `hibernate_resume_nonboot_cpu_disable()`. Only a zero return proceeds to `local_irq_disable()`, sets `SYSTEM_SUSPEND` and enters `syscore_suspend()`. Reaching this target therefore extends the positive pre-CPU result through successful secondary CPU disable and IRQ disable; it does not execute or qualify any syscore callback, processor-state save, architecture restore, memory copying or restored-driver recovery. An absent return witness remains inconclusive; it cannot identify CPU-disable failure separately from recovery or observation failure.

The module `mba_hibernate_cold_pre_syscore` has experiment metadata `mba_cold_boundary=pre-syscore-v1`. It registers one ftrace IP-redirection hook, loads disarmed and accepts one root-only lowercase 24-character `arm_prefix` after registration. It preserves that prefix in a read-only parameter, latches exactly one interception, disarms and redirects repeated target invocations until unloaded. Read-only state supplied during module insertion is rejected. Its `observed_irqs_disabled`, `observed_online_cpus` and `observed_boundary_valid` parameters record the first target observation. A valid boundary requires disabled IRQs and exactly one online CPU. A mismatched observation still redirects to `-ECANCELED`, remains latched and must refuse a positive witness; it never allows execution into syscore or atomic restore.

The target callback uses only RAM observations and instruction-pointer redirection. It neither invokes EFI/runtime services nor logs, allocates, sleeps, calls CPU recovery or installs kretprobes. This avoids a missed return-probe instance allowing the successful CPU-disable call to proceed into atomic restoration.

The ftrace operation requires `FTRACE_OPS_FL_PERMANENT`. The pinned kernel refuses registering this operation when global ftrace is disabled and refuses later disabling global ftrace while the operation remains registered. An ordinary non-permanent registration can succeed while tracing is disabled, which would allow the target body to execute without the abort. Any earlier private module compiled without the permanent flag is unqualified and must not be embedded or used. The retained arm/interception checks also prevent a concurrent winning callback, disarming race or consumed-before-armed window from allowing another target invocation through; only the winning callback records observations.

The same permanent-registration requirement now applies to the source of the pre-CPU profile for any future build. Both profiles declare `mba_cold_permanent=v1`; the closed build contract must reject supplied binaries without that exact modinfo field even when their SHA/source-version identities are provided. Its consumed images, vectors and historical proof remain untouched; modifying source does not retroactively qualify an older compiled artifact. The pinned registration/sysctl harness tests both profiles' actual operation flags and checks both source declarations.

The replacement returns `-ECANCELED` before the original `syscore_suspend()` body or its wakeup check/callbacks execute. The kernel then follows `Enable_irqs`, restores `SYSTEM_RUNNING`, enables IRQs, reenables secondary CPUs and cpuidle, performs platform cleanup and noirq/early device recovery, and returns through outer main-device and console recovery. Do not call `syscore_resume()` on this bypass: no syscore callback ran. Do not turn a successful completed `syscore_suspend()` return into an error without balancing its callbacks; that would take a different and unsafe cleanup path.

Later integration should retain the independently audited normal/pending swap gate and direct-only synchronous resume wrapper from the pre-CPU design, while assigning new module paths, experiment/version metadata and witness magic/name such as `MBSC` and `OmarchyT2ColdPreSyscoreReturned<PREFIX>` rather than reusing `MBCP`. Positive witness creation must occur only after synchronous resume returns to recovered userspace, with exact image/module/vector identity, consumed arm, one interception, `observed_irqs_disabled=Y`, `observed_online_cpus=1`, `observed_boundary_valid=Y`, the existing ordered restore stages and the normal consumed swap signature. Invalid observations may receive a separate failure record after recovery, but never a successful boundary witness. A witnessed controlled abort must stop in the visible recovery shell instead of continuing to normal userspace.

`python3 packages/t2-suspend/tests/test-cold-pre-syscore.py [pinned-kernel/power/hibernate.c]` compiles userspace harnesses using the actual module callbacks/initialization plus the actual pinned kernel `resume_target_kernel()` and `hibernation_restore()` bodies and the complete ftrace registration/permanent-operation/sysctl guard functions. It defaults to the host-local research tree and rejects caller source whose SHA-256 differs from `989a5fef5d7843518d31815c88bf1a1f35a51a176f6fb8fe1d3e6e0f1dbc9bf3`, sibling `kernel/trace/ftrace.c` differing from `b465ec022f67f3367a758bcc915dafed843c22e04e098a1dba3648aea07f85e3`, or `include/linux/ftrace.h` differing from `fbe362770824c729f496b8fe22c68d68d07bd5afb2eb0d2561198c3f9d910927`. This host-source test is intentionally excluded from the portable aggregate, like the existing PCI firmware-master harness. All kernel effects are mocked; the kernel source is read-only and no host module, swap, EFI or PM operation occurs. Coverage includes valid/invalid observations, one-use/repeated/concurrent interception, insertion and registration unwind, CPU/platform/device errors, exact IRQ/CPU/device recovery order, disabled permanent registration refusal, later global-disable refusal, disabling after unregister, and an ordinary-registration control exposing the original bypass. These tests prove source control-flow behavior, not real ftrace patching or hardware safety.
