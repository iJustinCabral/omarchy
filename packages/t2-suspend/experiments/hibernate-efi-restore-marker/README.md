# EFI cold-restore boundary marker

This is an offline diagnostic for the next distinct hibernation pair, not a fix or permission to repeat the terminal v5 S4 vector. It uses the unchanged production kernel and a separate EFI variable, `OmarchyT2RestoreStage-5e17d2ad-021f-4d45-a8e5-f4c191983e27`. A future guarded source attempt must prewrite exactly 17 bytes: `MBRS`, the first 12 bytes of that pair's full transition vector, and stage 0. Loading the module is disarmed; its root-only `arm_prefix` parameter accepts the exact 24-character lowercase prefix only after checking the prewritten EFI value, attributes and nonblocking EFI support. The module does not create or delete the variable.

After arming in the restore initramfs before the `resume` hook, nonblocking EFI writes record monotonic stages: 1 at `swsusp_check()` entry, 2 only on its successful return after swap-signature reset, 3 at `swsusp_read()` entry, 4 only on successful full image-read return, 5 at `hibernation_restore()` entry, 6 at `dpm_suspend_start()` entry, and 7 at `dpm_suspend_end()` entry after the first device-quiesce pass. A failed check/read return or EFI write disarms later stages. The module does not redirect control flow or mark any stage after the late/noirq boundary, where an EFI runtime write would be unsafe. Stage 7 does not prove atomic memory replacement, restored-device usability or a fixed hibernation path.

The pinned production kernel exposes all five ftrace targets and both kretprobe functions. The extracted-C callback test covers ordered stages, out-of-order refusal, return errors, repeated callbacks and EFI-write failure. The first `W=1` build against exact installed `7.2.6-arch2-Watanare-T2-2-t2` headers passed with source SHA-256 `30aaab3231962cd489b2769d2fe6019ff6d40fb7585a5c1ba5917851a3f173e0`, private module SHA-256 `60480f8e48e3d7c4ce8da55389a05995172a18730cdaec60bd70b6597bdd6b91` and source version `3119365A09AED2D4CD65DD6`; the installed `pahole` is one version older than the kernel build's but module BTF generation completed. The focused callback test and aggregate T2 shell suite pass. On healthy stock boot `f51e71c8-ec5d-476c-b31e-f9c0a059cfc9`, this exact module loaded disarmed with `arm_prefix=0`, `stage=0`, `last_efi_status=0` and unloaded; its EFI variable remained absent. A root-owned mode-0600 offline copy is `/var/lib/omarchy-t2-restore-marker/mba_hibernate_efi_restore_marker.ko`. It has not been inserted into the Mac initramfs or armed, and no new S4 vector has been prepared or attempted. The restore-initramfs hook and guarded source pre-arm integration must be built, independently audited and ordinary-boot qualified before any new hardware attempt.
