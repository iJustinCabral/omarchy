# Cold pre-CPU controlled-abort prototype

**NOT DEPLOYABLE.** This standalone prototype has no builder, auditor or source-runner integration. Its absent-marker path is intentionally inert for an ordinary boot, but EFI absence does not prove that swap has no pending hibernation image. Deployment requires an independent normal-swap/pending-attempt gate: absent or lost marker evidence with a pending attempt must stop before `resume`. Do not stage or execute this prototype until that gate and its fault tests exist. Compilation and offline tests do not qualify Apple firmware, cold restoration or manual recovery.

The external module preserves the production `.linux` and `.cmdline` sections. It redirects `hibernate_resume_nonboot_cpu_disable()` to `-ECANCELED` after late/noirq device quiesce and platform preparation, before secondary CPU disable or atomic memory copying. The kernel then follows its existing CPU/platform/noirq/early/main-device recovery path. The callback performs only RAM bookkeeping and instruction-pointer redirection; it makes no EFI call, logs nothing and installs no kretprobe. After the first interception its counter remains 1, its arm becomes false, and repeated target calls still abort until the module is unloaded. Insertion-time arm/vector/counter forgery is refused.

The root-only `arm_prefix` parameter accepts a single 24-character lowercase vector prefix after registration. Its getter reports arm state as `0/1`; `arm_consumed` reports `N/Y`; `interceptions` and `vector_prefix` are read-only. The hook verifies the exact vector against the stage-0 EFI marker before arming. The module itself does not authenticate EFI or a full pair vector; later integration must bind the prefix to the full guarded attempt and exact artifacts.

The proposed regular hook order is `encrypt`, the existing restore marker, `omarchy-t2-cold-pre-cpu`, stock `resume`, then `omarchy-t2-cold-pre-cpu-return`. The existing builder/auditor requires the restore marker immediately before `resume`; later integration must deliberately adapt and independently audit that invariant, preserving fail-closed arming and ensuring both diagnostic hooks surround the synchronous resume invocation. Do not substitute `run_latehook`, which executes after root mounting. Successful image restoration would never return to the restore initramfs, so the result hook describes a deliberate aborted restore only.

The bundle interface is `/usr/lib/omarchy-t2-cold-pre-cpu/{functions,abort.ko,abort.sha256,abort.srcversion,restore.variable}`. The variable selector contains exactly `OmarchyT2RestoreStage-5e17d2ad-021f-4d45-a8e5-f4c191983e27` or its existing `OmarchyT2RestoreStageV2` variant. No new version is inferred. Before insertion/arming, the pre-hook retains `/run/omarchy-t2-cold-pre-cpu.intent` containing the prefix. Insertion verifies the embedded module hash before loading and the loaded source version afterward. An interrupted arm remains an active diagnostic intent and cannot silently become inert.

After stock `resume` returns, the result hook requires matching intent/vector, exact on-disk and loaded module identities, raw vector-matching EFI stage 7, consumed arm, disarmed state and exactly one interception. It then exclusively creates `OmarchyT2ColdPreCpuReturned<PREFIX>-5e17d2ad-021f-4d45-a8e5-f4c191983e27`, with EFI attributes 7 and payload `MBCP`, the ASCII 24-character prefix and byte 1, and verifies exact readback. No existing witness is overwritten or removed. The witness positively identifies completed cold quiesce/platform preparation and returned failure recovery, with atomic copying intentionally omitted. Stage 7 without this witness remains inconclusive: quiesce, platform preparation, recovery or witness production could have failed.

Both failed validation and successful witnessed interception quit Plymouth and replace PID 1 with a visible recovery shell. A witnessed controlled abort is never reported as successful hibernation or allowed to continue into normal userspace. All consumed historical vectors, guards and EFI evidence must remain preserved; this prototype does not authorize another PM transition or repeating a failed vector.

Run `python3 packages/t2-suspend/experiments/hibernate-cold-pre-cpu/test-offline.py` from the repository. It extracts the actual C arm/callback/init/exit functions into a userspace fault harness and exercises the real busybox ash and mkinitcpio quiet logger against synthetic files. The resume operation, module insertion and sysfs state transitions are simulated; no host module, EFI variable, swap image or power state is touched. Tests cover insertion rejection, filter/registration failure and unwind, disarmed registration, one-use arming, repeat interception, exact deferred witnesses, identity/vector/stage/counter failures, stale evidence and failed witness readback. These tests cannot establish the required absent-marker pending-image gate, real initramfs hook ordering or hardware safety.
