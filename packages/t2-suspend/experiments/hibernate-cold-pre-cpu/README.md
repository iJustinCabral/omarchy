# Cold pre-CPU controlled-abort prototype

**NOT HARDWARE-QUALIFIED.** The independent pending-image gate and fault tests are implemented here; deployment still requires reviewed builder/auditor/source-runner integration and a fresh guarded diagnostic vector. EFI absence alone never authorizes resume. No part of this prototype authorizes staging, rebooting or a PM transition. Compilation and offline tests do not qualify Apple firmware, cold restoration or manual recovery.

`read-swap-header.c` opens only the resolved `/dev/mapper/root` block node read-only, verifies its pinned device number against both the opened descriptor and the named mapping, checks device-size and offset arithmetic, and reads exactly 4096 bytes. Only the normal `SWAPSPACE2` signature with swap version 1 produces `NORMAL`; the exact Linux `S1SUSPEND` signature produces `PENDING`. Unknown signatures, legacy swap formats, wrong device identity, short/interrupted reads and all syscall failures are inconclusive and rejected. The pinned device `/dev/mapper/root`, page offset `1923214` and device number `253:0` must match the immutable bundle, the unique explicit kernel command-line resume arguments and the kernel resume-offset sysfs value. This excludes an eligible image at the only permitted resume location; a normal signature does not prove that no prior attempt occurred, because `swsusp_check()` consumes the image signature before later restore can fail.

An absent marker permits an ordinary boot only when this independent header gate reports `NORMAL` and neither diagnostic module nor intent exists. A pending image with absent/lost marker, or a present stage-0 marker without a pending image, fails closed. The `resume` wrapper rechecks the header, exact identities and armed state immediately before invoking the pinned stock hook synchronously. It rejects an executable `systemd-hibernate-resume`, whose EFI-location branch could select another image; the diagnostic `install/resume` omits that helper, and integration must independently audit its absence. The ordinary return path rechecks normal swap; a witnessed diagnostic return also requires a normal consumed signature. No hook writes swap or clears historical guards.

The external module preserves the production `.linux` and `.cmdline` sections. It redirects `hibernate_resume_nonboot_cpu_disable()` to `-ECANCELED` after late/noirq device quiesce and platform preparation, before secondary CPU disable or atomic memory copying. The kernel then follows its existing CPU/platform/noirq/early/main-device recovery path. The callback performs only RAM bookkeeping and instruction-pointer redirection; it makes no EFI call, logs nothing and installs no kretprobe. After the first interception its counter remains 1, its arm becomes false, and repeated target calls still abort until the module is unloaded. Insertion-time arm/vector/counter forgery is refused.

The root-only `arm_prefix` parameter accepts a single 24-character lowercase vector prefix after registration. Its getter reports arm state as `0/1`; `arm_consumed` reports `N/Y`; `interceptions` and `vector_prefix` are read-only. The hook verifies the exact vector against the stage-0 EFI marker before arming. The module itself does not authenticate EFI or a full pair vector; later integration must bind the prefix to the full guarded attempt and exact artifacts.

The required regular hook order is `encrypt`, then the consecutive chain `omarchy-t2-cold-pre-cpu`, the existing `omarchy-t2-restore-marker`, `resume`, and `omarchy-t2-cold-pre-cpu-return`. The regular name `resume` resolves to the diagnostic wrapper, which invokes the exact bundled stock hook. This preserves the existing marker-immediately-before-resume invariant. Both the pure `audit-order.py` and runtime functions reject missing/duplicate/reordered hooks or diagnostic hooks scheduled as early/late/cleanup/emergency hooks; command-line hook disabling is rejected. Integration must also pin the wrapper, helper, bundle, stock hook and installer bytes and audit their actual scheduled/executable presence. Do not substitute `run_latehook`, which executes after root mounting. Successful image restoration would never return to the restore initramfs, so the result hook describes a deliberate aborted restore only.

The bundle interface is `/usr/lib/omarchy-t2-cold-pre-cpu/{functions,abort.ko,abort.sha256,abort.srcversion,restore.variable,header-reader,header-reader.sha256,resume.device,resume.offset,resume.devnum,stock-resume,stock-resume.sha256}`. The binary `header-reader` is compiled from `read-swap-header.c` and accepts device path, page offset, major number and minor number in that order. The install hooks consume the prepared `OMARCHY_T2_COLD_PRE_CPU_BUNDLE`, copy the helper with mode 0700 and other bundle files with mode 0600, and add the diagnostic runtime hooks. The variable selector contains exactly `OmarchyT2RestoreStage-5e17d2ad-021f-4d45-a8e5-f4c191983e27` or its existing `OmarchyT2RestoreStageV2` variant. No new version is inferred. Before insertion/arming, the pre-hook retains `/run/omarchy-t2-cold-pre-cpu.intent` containing the prefix. Insertion verifies the embedded module hash before loading and the loaded source version afterward. An interrupted arm remains an active diagnostic intent and cannot silently become inert.

After stock `resume` returns, the result hook requires matching intent/vector, exact on-disk and loaded module identities, raw vector-matching EFI stage 7, consumed arm, disarmed state and exactly one interception. It then exclusively creates `OmarchyT2ColdPreCpuReturned<PREFIX>-5e17d2ad-021f-4d45-a8e5-f4c191983e27`, with EFI attributes 7 and payload `MBCP`, the ASCII 24-character prefix and byte 1, and verifies exact readback. No existing witness is overwritten or removed. The witness positively identifies completed cold quiesce/platform preparation and returned failure recovery, with atomic copying intentionally omitted. Stage 7 without this witness remains inconclusive: quiesce, platform preparation, recovery or witness production could have failed.

Both failed validation and successful witnessed interception quit Plymouth and replace PID 1 with a visible recovery shell. A witnessed controlled abort is never reported as successful hibernation or allowed to continue into normal userspace. All consumed historical vectors, guards and EFI evidence must remain preserved; this prototype does not authorize another PM transition or repeating a failed vector.

Run `python3 packages/t2-suspend/experiments/hibernate-cold-pre-cpu/test-offline.py` from the repository. It extracts the actual C arm/callback/init/exit functions into a userspace fault harness and exercises the real busybox ash and mkinitcpio quiet logger against synthetic files. Additional flow tests use the actual mkinitcpio hook dispatcher, existing restore marker and installed stock resume source, with only absolute filesystem prefixes relocated into fixtures. Module insertion and the stock sysfs write are mocked; no host module, EFI variable, swap image or power state is touched. Header-reader tests include its actual C source with read-only syscall mocks. Coverage includes insertion rejection, registration unwind, one-use/repeated interception, independent normal/pending/unknown/error classification, device/size/overflow/short-read faults, command-line mismatch/duplicates/noresume/disabled hooks, immediate pre-resume state loss, systemd alternate-location rejection, exact deferred witnesses, stale evidence and failed readback. Offline tests establish implementation behavior, not physical hardware or actual staged initramfs qualification.
