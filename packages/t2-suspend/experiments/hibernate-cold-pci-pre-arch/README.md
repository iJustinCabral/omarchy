# Combined cold PCI guard and pre-architecture abort

This private `cold-pci-guard-pre-arch-abort-v1` runtime uses the unchanged `mba_hibernate_cold_pre_arch` abort module and an explicitly pinned `mba_hibernate_cold_pci_guard` module. Its exclusive return identity is `MBPG` / `OmarchyT2ColdPciPreArchReturned<PREFIX>`. It does not change the historical MBAR profile or its source pins.

The bundle lives at `/usr/lib/omarchy-t2-cold-pci-pre-arch/` and contains `functions`, `abort.ko`, `abort.sha256`, `abort.srcversion`, `guard.ko`, `guard.sha256`, `guard.srcversion`, `restore.variable`, `header-reader`, `header-reader.sha256`, `resume.device`, `resume.offset`, `resume.devnum`, `stock-resume`, and `stock-resume.sha256`. The hook order is `encrypt`, `omarchy-t2-cold-pci-pre-arch`, `omarchy-t2-restore-marker`, synchronous `resume`, and `omarchy-t2-cold-pci-pre-arch-return`. Diagnostic hooks in early, late, cleanup or emergency phases are forbidden. Existing candidate late payload remains available only on the ordinary no-image path.

Only an exact pending V2 restore marker and pending swap header permit explicit guard insertion. The guard must actually bind the otherwise-unbound BCE function; successful insertion without binding is insufficient. Both modules must have exact file and loaded source identities and pristine parameters before one-use arming. The ordinary NORMAL path loads neither module, requires both absent and BCE/SEP/audio unbound, and therefore cannot compete with the later candidate BCE payload. No guard auto-loading or ordinary guard unload is part of this protocol.

The return hook requires the exact consumed abort prefix, one interception, IRQs disabled, one online CPU and valid boundary observations. It also requires the exact guard prefix, consumed arm, disarmed state, one gate, inactive completed recovery and no sticky failure, exact PCI ownership, normal consumed swap signature, Entered/Armed witnesses, and no same-vector return witness from another protocol. Only recovered initramfs execution creates MBPG. The diagnostic then stops visibly before normal boot and retains modules for inspection. Partial preparation, failed gates and missing completion stop without a positive witness; the runtime never unloads or reopens DMA to recover a partial attempt.

Recovery replaces init with the interactive shell. If that console redirection or exec fails and returns, the hook exits init explicitly; mkinitcpio ignores ordinary hook return codes, so returning a failure alone would not prevent later resume or payload execution.

These checks qualify controlled recovery under this candidate, not posted-DMA drain, firmware isolation, atomic image restoration or resumed source userspace. The outer runner must provide the fresh durable full pair-vector guard, attended recovery acceptance and exact image/artifact audit. This runtime alone is not a hardware-test authorization or a hibernation fix.
