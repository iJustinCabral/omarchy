# Offline cold pre-relocation controlled-abort prototype

This standalone prototype is not built, installed, loaded, integrated into an initramfs, or hardware qualified. The next hardware experiment remains undecided. This abort boundary could support future qualification of the separate cold PCI guard; it is not a hibernation fix or a scheduled mapping-only S4 test. All consumed pre-CPU, pre-syscore, pre-architecture and historical warm post-relocation vectors remain consumed.

The module fixes its permanent SAVE_REGS/IPMODIFY ftrace hook at `relocate_restore_code()` entry and declares boundary `pre-relocate-v1`. In the pinned x86-64 source, this target follows successful `set_up_temporary_mappings()` and assignment of `temp_pgt`, but precedes restore-code allocation, copying, NX changes, TLB flush and `restore_image()`. A controlled return would establish temporary text/direct-map construction and recovery under instrumentation; it would not establish relocation, a switch to temporary CR3, image-page replacement, restored source drivers or successful hibernation. `CONFIG_HIGHMEM` is absent in the pinned configuration; the caller's `restore_highmem()` is its actual inline no-op.

The implementation retains the cold pre-architecture contract: disarmed insertion only, permanent registration, one root-only lowercase 24-character arm prefix, sticky consumed identity and one winning RAM observation. Valid observations require disabled IRQs and one online CPU (`Y/1/Y`). Invalid observations and losing/repeated callbacks still redirect to the `notrace` stub returning `-ECANCELED`, without overwriting observations. Callback and stub perform no logging, allocation, EFI/runtime service, FPU operation, return probe or cleanup. The ordinary caller releases image safe pages, restores processor state, resumes syscore and recovers IRQs/CPUs/platform/devices. Natural mapping failure follows that same nonzero-return recovery without reaching the hook or producing positive observations.

Installed build `vmlinux` matches that Build ID and the complete production `.text` SHA-256 `82adac9424f7b11cbd9a3daff462b0e2d6f8edbbfd10c8806a9ad51b8d5c687b`. The audited production body commits `temp_pgt`, calls the ftrace-capable relocation entry before its first allocation, branches to ordinary return on nonzero relocation result, and calls `restore_image()` only on zero. The live ftrace target is present. These facts establish production target/order availability; this module's registration and interception remain untested. No absolute symbol address is a runtime pin. The older diagnostic `vmlinux` in the pinned source tree is not a production artifact.

Run `PYTHONDONTWRITEBYTECODE=1 python3 packages/t2-suspend/tests/test-cold-pre-relocate.py [pinned-kernel/power/hibernate.c]`. The test deliberately reuses the pre-architecture runner's generated host fixtures through checked single replacements rather than duplicating its large one-use/recovery/ftrace harness. It runs that baseline, then compiles this module's actual extracted callback/arming/init/exit bodies, actual pinned `set_up_temporary_text_mapping()`, `alloc_pgt_page()`, `set_up_temporary_mappings()`, `swsusp_arch_resume()`, caller bodies and permanent ftrace guards. Source hashes and the production source configuration fail closed. Four/five-level mapping allocation failures, direct-map failures, successful mapping interception, disarmed relocation failure, and a direct architecture-body control supplement the inherited invalid/repeated/concurrent/registration/recovery cases. Hardware page tables, allocation helpers, mapping helpers, relocation/assembly and PM effects are mocked; this cannot establish physical mapping or recovery correctness. The test builds userspace C harnesses only, with no module build/load, boot image, EFI or power operation.

Additional pinned architecture sources are `arch/x86/power/hibernate_64.c` SHA-256 `615083b225388dc517a7c4d25f85e051b920d27bb992b33778a730c7b7fe5afd` and `arch/x86/power/hibernate.c` SHA-256 `550ce004ac844ccc1027b7e1a92d1fd805189405f573fe0973f052238fa0df1b`. Any future integration must use a distinct closed profile, return witness, exact artifact identity and durable one-use vector, preserve production `.linux` and `.cmdline` byte-for-byte, preserve existing consumed evidence, and receive independent review plus attended recovery qualification. No shared PERST operation is justified by this prototype. Host Intel VT-d and firmware DART remain distinct boundaries. Clearing PCI mastering would be a separate experiment and does not itself prove posted DMA drained.
