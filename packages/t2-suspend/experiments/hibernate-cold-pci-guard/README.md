# Offline cold PCI guard prototype

This private external-module prototype is not installed, loaded, built as a kernel module, included in an initramfs, or hardware qualified. It does not replace the production kernel or command line. It is not a hibernation fix, a durable attempt runner, or permission to retry a terminal vector.

The driver claims only the otherwise-unbound Apple BCE function and acquires references to the exact same-slot ANS/BCE/SEP/audio functions. It rejects unexpected IDs and bound SEP/audio drivers, requires ANS to use the ordinary `nvme` PCI driver, and maps only the standard ANS status register range for reads. It does not enable any PCI device, request IRQs, initialize BCE firmware, allocate DMA queues, or reset ANS. Probe failures release every acquired reference and mapping. Successful probe temporarily disables asynchronous PM for all four siblings and remove restores their original policy.

Arming is a one-use sysfs operation after probe, with a 24-character hexadecimal vector prefix. Insertion-time parameter overrides cannot pre-arm the module. The prefix is an identity token only; an eventual runner must independently bind it to a fresh durable attempt guard and exact image/module hashes. The prototype has no EFI or swap-header writes and is not integrated into the existing builder or runners.

Read-only sysfs parameters expose `gates`, `gate_active`, and sticky `gate_failed` in addition to the arm identity. Every attempted gate begins with `gate_failed=Y`; only completed clearing and snapshot scrubbing set it to `N`. Subsequent recovery failures latch it back to `Y`. `.complete` clears `gate_active` but never erases failure. An eventual returned-abort runner would require one gate, consumed arm, inactive completed recovery, no latched failure, exact identities, and its independently verified resume-boundary witness. These parameters alone cannot prove atomic restore, physical DMA inactivity, or success of a cold hibernation restoration. On successful atomic replacement the restore-kernel module and its parameters cease to exist.

The gate runs from `.freeze_noirq`, after the complete image has been read and all ordinary main quiesce callbacks have completed. It refuses before mutation unless ANS has no Linux PCI enable references, its COMMAND bus-master bit is clear, and its status registers prove either a reset-disabled controller or completed normal shutdown. The latter is necessary because Linux 7.2.6 `nvme_simple_suspend()` uses `shutdown=true`: `nvme_disable_ctrl()` leaves CC.EN set and waits for CSTS.SHST=complete. All-ones registers, enabled Linux ownership, active ANS mastering, in-progress shutdown, and live controller state fail closed.

The gate reads every original master bit before changing anything, clears and verifies all four siblings, then saves their disabled PCI state. It explicitly masks MASTER out of each saved COMMAND dword even when a clear or optional-capability save failed. It never restores mastering in a failed gate or `.thaw_noirq`. This matters because the pinned `pci_pm_thaw_noirq()` restores saved configuration before calling the driver. Original master bits are restored only from `.complete`, which follows every ordinary main recovery callback; any new ANS master bit enabled by its reset path is retained. A successful atomic restore discards the entire restore-kernel guard and resumes the separate candidate driver's saved state.

Run the extracted-source fault harness with the pinned source tree:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 packages/t2-suspend/tests/test-cold-pci-guard.py /home/jjc/.local/state/codex-mba-autonomous/kernel-readback-input/linux-7.2.6
```

The harness compiles real prototype probe/gate/recovery functions and actual pinned generic PCI freeze/thaw noirq, main thaw, and complete wrappers. It exercises missing siblings, mapping failure, driver conflicts, reference cleanup, ANS proof refusals, completed shutdown, every admissible master mask, failed clears and capability saves, saved COMMAND replay, delayed restoration, one-use refusal, and read-only outcomes. The real main thaw wrapper performs no generic reenable when the guard's PM table has no `.thaw`; a positive control checks that devices without a PM table do take the generic reenable branch. The real complete wrapper dispatches the guard's completion after simulated global main recovery, preserving ANS mastering newly enabled for fresh queues. PCI/MMIO accesses and unrelated platform plumbing are stubs; no host PCI or PM operation runs.

Unverified risks remain: standard ANS status registers must be valid and sufficient on the physical T2 implementation; clearing MASTER does not itself prove that every previously posted DMA transaction drained; firmware can change PCI state after the gate; asynchronous policy changes require a quiescent load/unload context; and forced unbinding during active PM is unsupported. PCI config reads inside `pci_save_state()` do not individually propagate their status, so an inaccessible function remains a platform recovery risk even though saved MASTER is scrubbed and the operation refuses atomic restoration. Ordinary root recovery, PCI callbacks, and firmware behavior are not proven by the harness. A separately reviewed integration and a new attended one-use hardware vector would be required for any physical qualification.
