# Cold pre-architecture controlled-abort prototype

This module and host-source harness are designed to extend the observed cold boundary to `swsusp_arch_resume()` entry; that boundary has not yet been demonstrated on hardware. The closed `cold_pre_arch` profile integrates the builder, initramfs hooks, image auditor and dedicated return reader, but is not hardware-qualified. Private build evidence is recorded in `docs/t2-suspend/HIBERNATION.md`. Existing pre-CPU and pre-syscore images, vectors, guards and witnesses remain consumed historical evidence. This prototype requires a distinct image, experiment identity and one-use vector; any private image must preserve production `.linux` and `.cmdline` byte-for-byte.

The fixed target is `swsusp_arch_resume()` entry, not `syscore_suspend()` exit. The pinned production `resume_target_kernel()` reaches it only after main/noirq device quiesce, platform preparation, successful secondary CPU disable, IRQ disable, successful `syscore_suspend()`, `save_processor_state()` and successful `restore_highmem()`. Unlike the pre-syscore boundary, this executes all successful syscore callbacks and processor-state save. The pinned source `.config` is X86_64 without CONFIG_HIGHMEM, so `restore_highmem()` is the actual `power.h` inline no-op. Reaching the target before replacement of target image pages is specific to this configuration: a generic HIGHMEM kernel may have swapped highmem pages before architecture entry. Loading the saved image into temporary buffers has already occurred.

The module `mba_hibernate_cold_pre_arch` declares `mba_cold_boundary=pre-arch-v1` and `mba_cold_permanent=v1`. Its permanent ftrace SAVE_REGS/IPMODIFY hook loads disarmed, rejects supplied insertion-time observation state and accepts one root-only lowercase 24-character `arm_prefix` after registration. The prefix and consumed arm persist. Exactly one winning callback records `observed_irqs_disabled`, `observed_online_cpus` and `observed_boundary_valid`, then disarms. Validity requires disabled IRQs and exactly one online CPU. Invalid observations still abort; concurrent losing callbacks, disarming races, consumed-before-armed windows and repeated calls redirect without fabricating or overwriting observations. One-use semantics apply to one loaded instance; a future initramfs's persistent vector guard must prevent unload/reload or reboot from replaying a hardware vector.

The callback only observes RAM and redirects the instruction pointer to a `notrace` stub returning `-ECANCELED`. Neither callback nor stub logs, allocates, sleeps, calls EFI/runtime services, invokes FPU operations, installs return probes or performs cleanup. The permanent flag is mandatory: the pinned ftrace code refuses registration while global ftrace is disabled and refuses later disabling while the hook remains registered. Ordinary non-permanent hooks permit that bypass. The historical `hibernate-pre-arch-resume-ftrace` experiment is a separate design and is not a substitute for this contract.

After the stub returns, the unmodified caller performs its normal failure suffix: a second no-op `restore_highmem()`, `swsusp_free()`, `restore_processor_state()`, watchdog touch and exactly one `syscore_resume()`, followed by `SYSTEM_RUNNING`, IRQ enable, secondary CPU/cpuidle recovery, platform cleanup, noirq/early and main device recovery and console recovery. No architecture restore body executes. The stub must not perform any of this cleanup itself: successful syscore suspend and processor save require the caller's existing balanced recovery. Natural syscore failure instead follows the caller's IRQ/CPU/device recovery path without processor save/restore or an additional caller `syscore_resume()`, and never reaches this hook. A failed `syscore_suspend()` may already unwind successful callbacks internally; this harness mocks those effects and checks only the caller's recovery contract.

Processor save is materially invasive: pinned `arch/x86/power/cpu.c` enters `kernel_fpu_begin()` inside `__save_processor_state()` before the wrapper saves the scheduling clock. The restore wrapper invokes `__restore_processor_state()`, which restores register/descriptor state and calls `do_fpu_end()`/`kernel_fpu_end()` before further clock, microcode and MSR restoration. A controlled return would establish that this actual recovery completed far enough to reach the restore initramfs; host tests cannot establish correct register, MSR, FPU or microcode behavior on hardware. Target availability and actual ftrace patching remain untested here. An absent witness cannot distinguish syscore failure, processor-save failure, missed interception or failure during cleanup.

Integration uses distinct `MBAR` / `OmarchyT2ColdPreArchReturned<PREFIX>` identity. Positive evidence may be written only after direct synchronous resume returns to recovered userspace with exact image/module/vector identity, consumed arm, one interception and exact observations `Y/1/Y`, existing ordered restore stages and the normal consumed swap signature. Invalid observations, natural syscore failure and absent interception must never receive a positive witness. All three profiles reject the other profiles' loaded modules, hooks and same-vector return witnesses. The witnessed diagnostic stops visibly instead of continuing to normal boot. Reaching this boundary would establish successful cold syscore suspend and processor save under instrumentation; it would not establish architecture image copying, atomic restoration, restored source drivers or successful hibernation.

Run `python3 packages/t2-suspend/tests/test-cold-pre-arch.py [pinned-kernel/power/hibernate.c]`. It defaults to `/home/jjc/.local/state/codex-mba-autonomous/kernel-readback-input/linux-7.2.6` and rejects changed input hashes. The test compiles userspace harnesses from actual module callbacks/initialization/flags, pinned kernel `resume_target_kernel()` and `hibernation_restore()` bodies, the actual no-HIGHMEM inline and actual complete ftrace registration/permanent/sysctl guard bodies. Source checks separately pin processor wrapper/FPU ordering and the production source configuration. All PM effects, processor operations and individual syscore callbacks are mocked. Coverage includes insertion/registration refusal and unwind, one-use/repeated/concurrent abort, invalid observations, exact balanced cleanup order, natural syscore and earlier device/platform/CPU failures, a synthetic highmem error (unreachable in the actual no-op configuration), disarmed architecture-body control, disabled registration refusal and later global-disable refusal. No module load, kernel build, image/staging, EFI or power operation occurs. The host-source test is intentionally outside the portable aggregate.
